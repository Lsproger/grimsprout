# Команда `/revert` — безопасный откат bot-коммита

**Фаза**: 4
**Статус**: done
**Приоритет**: high
**Зависимости**: нет

## Описание

Пользователь может ошибиться с целевой карточкой: например, добавить фото не тому растению, записать заметку не туда или выполнить другое мутационное действие по ошибке.

Нужен безопасный способ отменить такой bot-коммит прямо из Telegram, не заходя в git вручную и не переписывая историю ветки.

**Зачем**: снизить цену пользовательской ошибки и убрать ручной git-ремонт для типовых промахов в чате.

**Кто**: `editor+`, при этом расширенный режим для старых коммитов доступен только `admin`.

**Что**: Команда `/revert <short_sha> [--hard]`, которая ищет bot-коммит по короткому SHA и выполняет `git revert`, создавая новый коммит отката.

## Сценарии использования

### 1. Обычный откат свежего коммита
```text
User: отправил фото не в ту карточку
Bot: 📸 Фото сохранено...
     Коммит: a1b2c3d4e5

User: /revert a1b2c3d4
Bot: ⏳ Подтвердить откат коммита?
     🎯 Цель: a1b2c3d4e5
     📝 chore(auto): photo calathea_01
     🛡 Режим: default

User: [Подтвердить]
Bot: ↩️ Откат выполнен.
     Отменён: a1b2c3d4e5
     Коммит отката: f6g7h8i9j0
```

### 2. Админский hard mode для старого bot-коммита
```text
Admin: /revert deadbeef --hard
Bot: ⏳ Подтвердить откат коммита?
     🎯 Цель: deadbeef12
     🛡 Режим: hard
```

### 3. Ошибка поиска
```text
User: /revert abc1234
Bot: Не удалось найти коммит: commit not found for short sha: abc1234
```

## Требования

### Функциональные
- Команда `/revert <short_sha>` доступна из Telegram.
- Поиск цели идёт только в `repository.work_branch`.
- В обычном режиме рассматриваются только последние 20 bot-коммитов.
- Bot-коммит определяется по маркеру `GrimSprout: tg_id=<id>` в сообщении коммита.
- `--hard` расширяет поиск за пределы окна последних 20 коммитов, но доступен только `admin`.
- Откат выполняется только через `git revert`.
- Если `confirm_commits=true`, откат требует отдельного подтверждения.
- В `audit_log` пишутся успех и причины блокировки/ошибки.

### Нефункциональные
- История git не переписывается.
- Merge-коммиты не поддерживаются для этой команды.
- При конфликте `git revert` должен быть прерван, чтобы не оставлять репозиторий в промежуточном состоянии.
- Пользователь получает короткие и понятные диагностические сообщения.

- Команда покрывает фото-кейс, но спроектирована как универсальный откат любого bot-коммита.
